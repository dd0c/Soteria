Soteria

Host-based intrusion detection and integrity monitoring for Linux servers. Soteria keeps an approved, signed record of how a host should look, watches it as it changes, and tells you what deviates and where it cannot see.

What it watches

  • FilesSystem binaries, libraries, /etc, /boot and your own paths, with SHA-256, ownership, mode and capabilities, checked live through inotify and by scheduled scans.
  • Program executionEvery execution from the kernel audit stream: unknown or modified programs, unusual locations, suspicious lineage and privilege changes.
  • PersistenceSSH keys, shell startup files, systemd units, user services and cron, the places an intruder comes back through.
  • AccountsNew, removed or changed users and groups, extra UID 0 accounts, privileged groups, sudo rules and empty passwords.
  • Kernel and bootKernel version, boot parameters, Secure Boot state, and unknown, unsigned or out-of-tree modules.
  • ItselfChanges to its own configuration, rules and keys, unclean stops and every gap in its coverage are reported, never hidden.

How it works

After installation you inventory the host and approve the result. The baseline is signed with an Ed25519 key that only root holds; the daemon runs as an unprivileged soteria user with two read-only capabilities, so it can detect change but cannot approve it. Baselines are never updated automatically: after planned maintenance you review the differences and approve a new one.

Every alert names the rule that fired, the approved and current state, and what to check next. Alerts stay on the host in a local database and can be forwarded by email or webhook as they happen.

Footprint

On a 4 vCPU virtual machine: 0.1 % CPU when idle, 12 MiB of memory, a full scan of 50,000 files in under two seconds, and an alert about 0.3 seconds after a file changes. Details in the benchmarks.
